# TCP 粘包问题

## 什么是 TCP 粘包问题？

1. 什么是 TCP 协议？
   - 面向连接的、可靠的、基于字节流的协议
   - 优化策略
     - 组合
       - 目的：提高网络带宽的利用率，减少 TCP 协议头带来的开销
       - 原理：合并应用协议层多次写入的数据（如果每次写入的数据量太小）
       - 实现：Nagle 算法
     - 拆分
       - 原因：TCP 协议引入最大分段大小（Maximum Segment Size, MSS），如果应用层需要传输的字节数据大小超过 MSS，那么这个数据就会被拆分到多个数据包中，分别传送。
2. TCP 粘包是什么？
   - 本质：TCP 是无消息边界的字节流协议
     - 问题加剧：Nagle 导致多次发送被合并
     - MSS 或 网络传输 可能导致拆包
   - 现象：接收到的数据不是一条完整的信息，无法被正确解析

## 如何解决 TCP 粘包问题？

1. 应用层：自行设置消息边界，并引入缓冲区
   1. 约定每条信息的分隔符（终结符，Delimiter）
   2. 引入缓冲区概念
      1. 每次接收到数据时，将输入塞入缓冲区
      2. 检查缓冲区是否存在完整信息
         - 存在 -> 从缓冲区中拿出这条信息
         - 不存在 -> 不做操作
2. 操作系统层：关闭 Nagle 算法

## 🤔 我的疑问

**Nagle 算法的出现，是因为早期互联网的网络带宽资源紧张，现如今都已经是 5G 时代，操作系统还默认开启 Nagle 算法吗？**

- 我的电脑配置
  - Chip: Apple M4 Pro
  - OS: macOS Tahoe 26.3
  - Nagle: 默认开启
  - TCP_NODELAY: 默认关闭
- Why 感受不到粘包？
  - 本地回环（localhost）：没有真实网络环境 -> 极少分片
  - 发送频率低：手动输入 -> 发送间隔大
  - 数据量小：字节量小 -> 一发完
- TCP_NODELAY
  - 目的：应对 Nagle 策略
  - 现象：每次发送后，数据都会尽快发出去，不等待合并
  - 关于解决粘包问题
    - 有用：Nagle 引起的粘包问题
    - 无效：
      - 拆包
      - 接收端缓冲导致的粘连
